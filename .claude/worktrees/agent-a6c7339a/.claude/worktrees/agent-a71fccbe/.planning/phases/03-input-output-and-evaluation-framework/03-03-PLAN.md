**`pub struct EvaluationWorkspace`:**
- Fields (all private):
  - `scratch: Vec<f64>` -- single contiguous allocation for cache locality
  - `np: usize` -- number of grid points
  - `spin: Spin` -- spin mode
  - `dims: Dimensions` -- MGGA dimensions (superset per D-12)

**`impl EvaluationWorkspace`:**

- `pub fn new(np: usize, spin: Spin) -> Self`:
  - `let dims = Dimensions::mgga(spin);`
  - `let total = dims.total_output_components() * np;`
  - `Self { scratch: vec![0.0; total], np, spin, dims }`

- `pub fn zero_scratch(&mut self)`:
  - `self.scratch.fill(0.0);`

- `pub fn np(&self) -> usize { self.np }`
- `pub fn spin(&self) -> Spin { self.spin }`

- Private helper: `fn offset_range(&self, offset: usize, dim: usize) -> std::ops::Range<usize>`:
  - `let start = offset * self.np;`
  - `let end = start + dim as usize * self.np;`
  - Returns `start..end`

- `pub fn lda_scratch_mut(&mut self) -> LdaScratch<'_>`:
  Returns a struct with mutable slices into the scratch buffer for LDA fields:

      pub vrho: &'a mut [f64],    // next offset, len = dims.vrho * np
      pub v2rho2: &'a mut [f64],  // ...

      pub v4rho4: &'a mut [f64],

**`pub fn add_to_mix(dst: &mut [f64], coeff: f64, src: &[f64])`:**
- Matches libxc mix_func.c line 54 exactly:
  ```rust
  for (d, s) in dst.iter_mut().zip(src.iter()) {
      *d += coeff * *s;
  }
  ```
- This is the inner loop of mixed accumulation. Keep it simple, no SIMD (compiler will auto-vectorize).

**Auxiliary configuration struct:**
```rust
/// Configuration for one auxiliary functional in a mixed evaluation.
pub struct AuxiliaryConfig {
    pub alpha: f64,       // The functional's alpha parameter (e.g., 1.0 for LDA_X)
    pub weight: f64,      // The mixing coefficient
    pub thresholds: Thresholds,
}
```

**`pub fn evaluate_mixed_lda(input: &LdaInput, order: DerivativeOrder, output: &mut LdaOutput, auxiliaries: &[AuxiliaryConfig], workspace: &mut EvaluationWorkspace) -> Result<(), LibxcRsError>`:**

1. Assert workspace.np() == input.np() and workspace.spin() == input.spin() (or return error)
2. Zero the caller's output buffers: for each `Some(ref mut buf)` field, `buf.fill(0.0)`
3. Get `dims = Dimensions::lda(input.spin())`
4. For each auxiliary in `auxiliaries`:
   a. `workspace.zero_scratch()` -- critical per Pitfall 6
   b. Create a temporary `LdaOutput` pointing into the workspace scratch:
      ```rust
      let scratch = workspace.lda_scratch_mut();
      let mut scratch_output = LdaOutput {
          zk: Some(scratch.zk),
          vrho: Some(scratch.vrho),
          v2rho2: Some(scratch.v2rho2),
          v3rho3: Some(scratch.v3rho3),
          v4rho4: Some(scratch.v4rho4),
      };
      ```
      Note: This requires that LdaOutput can be constructed without validation when pointing to workspace scratch (since scratch is pre-sized correctly). If LdaOutput::new() does validation, use an internal constructor or construct directly since fields are pub.
   c. Call `dispatch_lda(input, order, &mut scratch_output, aux.alpha, &aux.thresholds)?`
   d. Accumulate into caller output: For each derivative field up to `order`:
      ```rust
      if let Some(ref mut dst) = output.zk {
          add_to_mix(dst, aux.weight, scratch.zk);
      }
      if let Some(ref mut dst) = output.vrho {
          add_to_mix(dst, aux.weight, scratch.vrho);
      }
      // ... etc for v2rho2, v3rho3, v4rho4
      ```
      Only accumulate fields at or below the requested derivative order.
5. Return `Ok(())`

**Important lifetime consideration:** The `workspace.lda_scratch_mut()` borrows workspace mutably. The `LdaOutput` pointing into scratch also borrows mutably. After `dispatch_lda` returns, we need scratch data to accumulate. This requires careful lifetime management:
- Option A: Have `dispatch_lda` write results back into scratch via the LdaOutput pointing to scratch. Then after dispatch returns, access scratch data to accumulate into output. This works because dispatch_lda copies CubeCL results into the output slices.
- Option B: Use raw slices with unsafe. Avoid this.
- Recommendation: Option A. The flow is: zero scratch -> dispatch_lda writes into scratch via LdaOutput -> read scratch to accumulate into output. Between steps, re-borrow scratch as needed.

If borrow checker issues arise with the scratch-based LdaOutput approach, restructure so that dispatch_lda returns Vec<f64> results directly (but this is less ergonomic). The simplest approach may be:
1. Create separate Vec<f64> scratch buffers for each LDA field sized from dims
2. Build LdaOutput pointing to those scratch vecs
3. Call dispatch_lda
4. Accumulate from scratch vecs into output
5. Reuse scratch vecs across auxiliaries (zero between uses)

This would mean EvaluationWorkspace provides the Vecs, not split_at_mut slices. Adjust workspace API if needed for ergonomics. The key invariant is: one allocation at workspace creation, zero during evaluation.
