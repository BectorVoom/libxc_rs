  <action>
Create `verify/tests/lda_x_stress.rs` as an integration test in the verify/ crate. This file focuses on edge cases and stress conditions NOT covered by the main oracle comparison in `lda_x_oracle.rs`.

Follow the same patterns established in `lda_x_oracle.rs` for oracle setup and kernel launch, but test different scenarios.

**Test categories:**

**1. Threshold boundary tests (`test_lda_x_threshold_boundary`):**
- Create densities exactly at the boundary: `[0.5e-15, 0.9e-15, 1.0e-15, 1.1e-15, 2.0e-15, 1e-14]`
- Run both Rust kernel and C oracle with `dens_threshold = 1e-15`
- For rho < dens_threshold: Rust output `zk` must be exactly 0.0
- For rho >= dens_threshold: Rust output must match C oracle at 1e-12
- Important: C libxc uses `p->dens_threshold` internally — set it via `xc_func_set_dens_threshold` if available, otherwise use the default and match it exactly in the Rust kernel call
- Test all derivative orders (exc through lxc) at threshold boundary

**2. Non-default alpha tests (`test_lda_x_nondefault_alpha`):**
- LDA_X (XC_LDA_X, ID=1) has one external parameter: `alpha` (scaling factor, default 1.0)
- Test with alpha values: [0.0, 0.25, 0.5, 1.0, 1.5, 2.0]
- For each alpha value:
  - Set alpha in C oracle via `xc_func_set_ext_params(func, &[alpha])`
  - Pass alpha as parameter to Rust kernel
  - Compare outputs at 1e-12 for exc, 1e-10 for vxc
- Verify alpha=0.0 produces zk=0.0 (no exchange)
- Verify alpha=2.0 produces 2x the energy of alpha=1.0 (LDA_X energy is linear in alpha)
- Use rho = 1.0 for simplicity, plus a few other densities

**3. Extreme density tests (`test_lda_x_extreme_density`):**
- Density values spanning 22 orders of magnitude: [1e-14, 1e-12, 1e-10, 1e-8, 1e-6, 1e-4, 1e-2, 1.0, 1e2, 1e4, 1e6, 1e8]
- Run both Rust and C oracle
- Assert: no NaN in any output (check with `f64::is_nan()`)
- Assert: no Inf in any output (check with `f64::is_infinite()`)
- Assert: relative error <= 1e-12 for exc for all non-threshold densities
- Test all 5 derivative orders

**4. Asymmetric spin polarization tests (`test_lda_x_pol_asymmetric`):**
- Spin pairs (rho_a, rho_b): [(0.999, 0.001), (0.001, 0.999), (0.9, 0.1), (0.1, 0.9), (1e-8, 1.0), (1.0, 1e-8), (1e-4, 1e-1)]
- These stress the zeta computation and spin-dependent branches
- Compare all derivatives against oracle
- Special attention to vrho components: vrho_a and vrho_b should differ for asymmetric spins

**5. Symmetric spin matches unpolarized (`test_lda_x_pol_symmetric_matches_unpol`):**
- For rho_total in [0.1, 1.0, 10.0, 100.0]:
  - Run unpolarized kernel with rho = rho_total
  - Run polarized kernel with rho_a = rho_b = rho_total/2
  - Assert zk values match within 1e-14 (tighter than oracle tolerance since this is self-consistency)
  - This validates the spin handling identity: f(rho, 0) = f(rho_a, rho_b) when rho_a = rho_b

**6. Large batch test (`test_lda_x_large_batch`):**
- Create 10000 density points: linearly spaced from 0.01 to 100.0
- Launch kernel (requires ceil(10000/256) = 40 workgroups)
- Run oracle for same 10000 points
- Compare all — tests that CubeCount calculation and bounds guards work for non-trivial sizes
- This catches off-by-one in the last workgroup (workgroup 40 has 10000 - 39*256 = 16 active threads out of 256)
