**Step 2: Create src/kernel/lda/lda_x.rs** — Hand-translate all 10 functions from `lda_x.c`.

CRITICAL translation rules (per D-12):
1. Preserve EXACT maple2c variable names: `t2`, `t3`, `t4`, `t6`, `t8`, `t10`, `t11`, `t15`, `t16`, `tzk0`, `tvrho0`, etc.
2. Preserve floating-point operation order: `a * b * c` stays as `a * b * c`, NOT `a * (b * c)`
3. Translate maple2c numeric literals as f64: `0.2e1` -> `2.0`, `0.3e1` -> `3.0`, `0.8e1` -> `8.0`, `0.375e1` -> `3.75`
4. `POW_1_3(x)` -> `pow_1_3(x)` from `crate::math::powers`
5. `my_piecewise3(c, x1, x2)` -> `piecewise3(c, x1, x2)` from `crate::math::piecewise`
6. `M_CBRT3` -> `crate::math::constants::M_CBRT3` (import at top)
7. `params->alpha` -> `alpha: f64` scalar parameter passed to kernel
8. `p->dens_threshold` -> `dens_threshold: f64` scalar parameter
9. `p->zeta_threshold` -> `zeta_threshold: f64` scalar parameter
10. Output accumulation: `out->zk[ip*...] += tzk0` -> `zk[ip] += tzk0` (per Pitfall 4, += semantics)
11. Bounds guard: every function starts with `let ip = ABSOLUTE_POS; if ip >= zk.len() { return; }` (per Pitfall 6)

**The 10 functions to translate:**

Each is `#[cube(launch_unchecked)]` annotated.

**Unpolarized functions** (5):
- `lda_x_exc_unpol(rho: &Array<f64>, zk: &mut Array<f64>, alpha: f64, dens_threshold: f64, zeta_threshold: f64)` — lines 19-42 of lda_x.c
- `lda_x_vxc_unpol(rho: &Array<f64>, zk: &mut Array<f64>, vrho: &mut Array<f64>, alpha: f64, dens_threshold: f64, zeta_threshold: f64)` — lines 48-82. Computes BOTH exc AND vxc (each higher order includes all lower orders).
- `lda_x_fxc_unpol(rho, zk, vrho, v2rho2, alpha, dens_threshold, zeta_threshold)` — includes exc+vxc+fxc
- `lda_x_kxc_unpol(rho, zk, vrho, v2rho2, v3rho3, alpha, dens_threshold, zeta_threshold)` — includes exc+vxc+fxc+kxc
- `lda_x_lxc_unpol(rho, zk, vrho, v2rho2, v3rho3, v4rho4, alpha, dens_threshold, zeta_threshold)` — includes all 5 orders

**Polarized functions** (5):
Same pattern but:
- `rho` array has interleaved spin components: `rho[ip * 2]` = spin-up, `rho[ip * 2 + 1]` = spin-down (per Pitfall 7)
- `vrho` has 2 components per point: `vrho[ip * 2]`, `vrho[ip * 2 + 1]`
- `v2rho2` has 3 components per point (up-up, up-down, down-down)
- `v3rho3` has 4 components per point
- `v4rho4` has 5 components per point
- Variable naming follows maple2c: `t2` tests `rho[2*ip]`, uses `my_piecewise3` on per-spin density
- The polarized kernel is significantly longer due to spin-up/spin-down cross terms

For each function, translate the C source line-by-line. Do NOT optimize, simplify, or reorder any expressions. The goal is bit-level equivalence with the C code.

IMPORTANT — output indexing pattern for higher derivatives in unpolarized mode:
- `zk[ip]` — 1 component (energy per particle)
- `vrho[ip]` — 1 component (d(exc)/d(rho))
- `v2rho2[ip]` — 1 component (d2(exc)/d(rho)2)
- `v3rho3[ip]` — 1 component
- `v4rho4[ip]` — 1 component

For polarized mode:
- `zk[ip]` — 1 component
- `vrho[ip * 2 + {0,1}]` — 2 components
- `v2rho2[ip * 3 + {0,1,2}]` — 3 components (aa, ab, bb)
- `v3rho3[ip * 4 + {0,1,2,3}]` — 4 components (aaa, aab, abb, bbb)
- `v4rho4[ip * 5 + {0,1,2,3,4}]` — 5 components

Verify these indexing patterns against `p->dim.zk`, `p->dim.vrho`, `p->dim.v2rho2` etc. from the C source.
