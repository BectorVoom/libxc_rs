  <action>
Create `tests/math_integration.rs` as an integration test file (Rust convention: files in `tests/` directory are integration tests that compile as separate crates).

This file verifies that math modules compose correctly when called through CubeCL. The key difference from inline unit tests: these test cross-module function calls through the CubeCL JIT compilation pipeline, catching issues like:
- CubeCL failing to inline cross-module #[cube] function calls
- Type mismatches between modules only visible after JIT compilation
- CubeCL IR generation failures when composing multiple #[cube] functions

**Test kernels to create:**

1. **DFT quantities composition kernel** — a `#[cube(launch_unchecked)]` function that:
   - Takes `rho: &Array<f64>` input and `output: &mut Array<f64>` 
   - Computes `wigner_seitz_rs(rho[ip])` for each point
   - This exercises: dft_quantities -> powers -> safe_cbrt chain
   - Verify against hand-computed values: for rho=1.0, rs = RS_CONST * pow_1_3(1.0) = 0.6203504908994
   - For rho=0.01, rs = RS_CONST * pow_1_3(100.0) = RS_CONST * 4.6415... = 2.878...
   - Test with 50 density values from 0.001 to 100.0

2. **Spin scaling composition kernel** — a `#[cube(launch_unchecked)]` function that:
   - Takes `zeta: &Array<f64>` input and `output: &mut Array<f64>`
   - Computes `spin_scaling(zeta[ip])` for each point
   - This exercises: spin -> powers -> safe_cbrt chain
   - Verify: spin_scaling(0.0) = 1.0, spin_scaling(1.0) = 2^(1/3) = 1.2599210498948732
   - Test with zeta values [0.0, 0.1, 0.25, 0.5, 0.75, 0.9, 1.0]

3. **Combined GGA-like kernel** — a `#[cube(launch_unchecked)]` function that simulates what a real GGA kernel does:
   - Takes `rho: &Array<f64>`, `sigma: &Array<f64>`, `output: &mut Array<f64>`
   - Computes: `let rs = wigner_seitz_rs(rho[ip]); let s = reduced_gradient_s(rho[ip], sigma[ip]); output[ip] = rs * s`
   - This exercises the full chain: dft_quantities + powers + constants all composed
   - Verify against explicit computation for known (rho, sigma) pairs

4. **erf sweep through CubeCL** — a `#[cube(launch_unchecked)]` function that:
   - Takes `x: &Array<f64>` input and `output: &mut Array<f64>`
   - Computes `erf_approx(x[ip])` for each point
   - This exercises: erf -> polynomials composition
   - Compare all 1000 outputs against libm::erf() with 1e-15 tolerance
   - This differs from the inline unit test by running 1000 points through a single kernel launch (batch behavior)

5. **Build quality gate** — not a kernel, but verification commands:
   - `cargo build --workspace` exits 0 with no warnings
   - `cargo test --workspace` exits 0
   - `cargo clippy --workspace -- -D warnings` exits 0

Use the launch infrastructure from Plan 02 (cpu_client, create_input_buffer, etc.) for all kernel launches.

The exact pattern depends on how CubeCL handles cross-crate #[cube] function calls — Claude's discretion on the approach that compiles.
