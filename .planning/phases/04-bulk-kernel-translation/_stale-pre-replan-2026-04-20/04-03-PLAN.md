**GGA translation extends the LDA pattern with sigma inputs and cross-derivative outputs.**

1. **Create `dispatch_gga` function** in `src/eval/dispatch.rs`:
   - Signature: `pub fn dispatch_gga(func_id: u32, input: &GgaInput, order: DerivativeOrder, output: &mut GgaOutput, thresholds: &Thresholds) -> Result<(), LibxcRsError>`
   - Follow the dispatch_lda pattern but:
     - Upload sigma buffer in addition to rho
     - Create output handles for all 15 GGA output fields (zk + vrho/vsigma + 3 FXC fields + 4 KXC fields + 5 LXC fields)
     - Match on func_id first, then delegate to functional-specific launch module
     - Zero all caller-provided output buffers before evaluation (same pattern as dispatch_lda)
     - Read back all populated output fields

2. **For each of 131 GGA functionals, translate one at a time (per D-08):**

   a. Read `libxc-master/src/maple2c/gga_exc/{name}.c`
   b. Create `src/kernel/gga/{name}.rs`:
      - Same `#[cube(launch_unchecked)]` pattern as LDA
      - Add `sigma: &Array<f64>` parameter after `rho`
      - Add GGA-specific output arrays: `vsigma`, `v2rhosigma`, `v2sigma2`, etc. at appropriate derivative levels
      - For unpolarized: sigma has 1 component per point, index as `sigma[ip]`
      - For polarized: sigma has 3 components per point, index as `sigma[ip * 3 + 0/1/2]` (sigma_aa, sigma_ab, sigma_bb)
      - Preserve exact maple2c variable names and FP operation order
      - Translate numeric literals systematically
      - Output accumulation via `+=`
      - Density threshold check at function entry
      - For functionals with `params->` in C: add each parameter as scalar f64 argument. Extract default values from the corresponding C header (e.g., `gga_c_pbe.c` includes a params section with defaults)
   c. Create `src/kernel/gga/launch_{name}.rs`:
      - Import BufArg (reuse from LDA or define GGA-local version)
      - One safe wrapper per kernel function
      - GGA wrappers have more buffer arguments than LDA (sigma input + cross-derivative outputs)
   d. Add module declarations to `src/kernel/gga/mod.rs`
   e. Wire into dispatch_gga match statement
   f. Verify compilation after each functional

**Special file:** `gga_x_lb.c` from `gga_vxc/` per D-04. May only implement vxc level.

**Key GGA differences from LDA (from Research Pattern 2):**
- 69 of 131 GGA functionals use `params->` (functional-specific parameters)
- Polarized sigma indexing: `sigma[ip*3 + component]` where component is 0 (aa), 1 (ab), 2 (bb)
- Output field count grows: VXC level adds vsigma; FXC adds 3 cross terms; KXC adds 4; LXC adds 5
- Some GGA functionals reference LDA sub-expressions (e.g., GGA built on LDA correlation). In the maple2c C code, these are inlined -- translate the inlined version directly.

**Recommended translation order (simplest first):**
Start with `gga_c_pbe.c` (well-known, moderate size ~6K lines) to validate the GGA pattern, then proceed alphabetically through the remaining 130 files.
