<objective>
Fix two correctness liabilities in mixed evaluation that activate the moment Plan 05-04 populates real metadata:

1. **CR-02**: evaluate_mixed_gga and evaluate_mixed_mgga use add_opt(dst, coeff, src) which silently does n = dst.len().min(src.len()) — truncating on length mismatch instead of erroring. Replace with add_opt_n(dst, coeff, src, len) taking explicit length, threading per-family per-field lengths from the top of each evaluate_mixed_* function (mirroring evaluate_mixed_lda_functional which already does this).

2. **CR-03**: evaluate_mixed_mgga's MGGA-aux branch consults only the aux's NEEDS_LAPLACIAN/NEEDS_TAU flags. Per mix_func.c:184-305, the parent's flags are also load-bearing — if parent doesn't need laplacian but aux does, the parent should not receive vlapl contributions. Gate accumulation on (aux_needs_lapl AND parent_needs_lapl).

Bonus collateral fixes: WR-10 (remove the dead let _ = (needs_lapl, needs_tau, needs_both); discard) and WR-11 (harden add_to_mix debug_assert to always-on assert).

Purpose: Numerical correctness for hybrid GGA / MGGA functionals once metadata is populated. The 10^-12 oracle tolerance depends on exact accumulation; truncation that omits a single trailing component would silently fail oracle tests (which become real after Plan 05-04 unignores them).

Output: Hardened mixed-evaluation accumulators with explicit-length helpers + parent-flag gates.
</objective>
