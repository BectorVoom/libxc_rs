<objective>
Clean up the root `Cargo.toml` per the recommendation in 05-REVIEW.md CR-06. The 108 `libxc-kernel-mgga-1a` through `libxc-kernel-mgga-37b` path-dependencies currently listed under `[dev-dependencies]` (lines 19-127) are **redundant**: they are already pulled in transitively via the aggregate `libxc-kernel-mgga` crate (in `[dependencies]`, line 14), which has all 108 sub-crates as its own `[dependencies]` and re-exports them as `pub use libxc_kernel_mgga_<batch> as batch<batch>;`.

The verifier flagged this as CR-06 BLOCKER on the assumption that the dispatch code at `src/eval/mgga_dispatch/batch*.rs` references the per-functional crates directly. **Investigation showed otherwise**: the dispatch code references `crate::kernel::mgga::batch17::...` which resolves through the aggregate `pub use libxc_kernel_mgga as mgga` in `src/kernel/mod.rs`. So the per-functional crates are accessible in production builds via the aggregate.

**Note on the GGA sub-crates (CR-06 scope clarification):** REVIEW.md CR-06 also mentioned "58 per-functional GGA sub-crates" as `[dev-dependencies]`. **Direct inspection of Cargo.toml shows this is inaccurate** — the root `Cargo.toml` `[dev-dependencies]` block (lines 16-127) lists only `approx`, `libm`, `libxc_rs-verify`, and the 108 `libxc-kernel-mgga-*` sub-crates. There are NO `libxc-kernel-gga-*` entries in either `[dependencies]` or `[dev-dependencies]` (the GGA aggregate `libxc-kernel-gga` at line 13 is the only GGA entry). The per-functional GGA sub-crates (58 of them: kernel-gga-1a through kernel-gga-22) are pulled in transitively via the GGA aggregate's own `[dependencies]`, exactly mirroring the MGGA structure. So this plan's scope is **MGGA-only cleanup** — there are no GGA dev-dep entries to remove. The executor MUST NOT search for or attempt to remove `libxc-kernel-gga-*` lines because none exist.

The fix is therefore **removal** (cleanup of duplicate path-deps), not "moving from dev-dependencies to dependencies".

Purpose: Cleanup-class fix that closes CR-06's surface problem (`[dev-dependencies]` listing of run-time crates) while preserving the actual dispatch wiring that's already correct.

Output: Smaller, cleaner root `Cargo.toml` with no functional change.
</objective>
