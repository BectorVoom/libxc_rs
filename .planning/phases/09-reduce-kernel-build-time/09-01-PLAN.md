<objective>
Remove sccache as rustc-wrapper to fix the sccache/incremental mutual exclusion that causes zero cache hits and adds IPC overhead on every compilation unit.

Purpose: sccache cannot cache incremental builds (all 3,710+ compilation requests are "Non-cacheable: incremental"), and sccache crashes with SIGSEGV on large crates like kernel-mgga-37. Removing it eliminates overhead and crashes while allowing incremental compilation to function properly.

Output: Updated .cargo/config.toml without rustc-wrapper line.
</objective>

Edit `.cargo/config.toml` to remove the `rustc-wrapper = "sccache"` line from the `[build]` section. Keep the `jobs = 3` setting and the comment explaining memory constraints. Update the header comment to note that sccache was intentionally removed because it cannot cache incremental builds (every request was "Non-cacheable: incremental") and it SIGSEGV'd on large kernel crates.

The file should become:

```toml
# Build time optimization for CubeCL kernel crates.
#
# Each kernel sub-crate (37 MGGA + 3 GGA) consumes 3-7 GB RAM during CubeCL
# proc macro expansion. With the default jobs=nproc (16), Cargo would try to
# compile many crates in parallel, exceeding available memory (24 GB) and
# causing swap thrashing.
#
# jobs = 3 keeps peak memory under ~21 GB (3 * 7 GB) while still allowing
# parallelism across independent crates.
#
# NOTE: sccache was removed because it cannot cache incremental builds
# (all requests were "Non-cacheable: incremental") and it crashed with
# SIGSEGV on large kernel crates (kernel-mgga-37). Incremental compilation
# is more valuable for this project's dev workflow.
[build]
jobs = 3
```
