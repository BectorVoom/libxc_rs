<objective>
Configure sccache as build compiler, disable incremental compilation (they are
mutually exclusive), and remove redundant per-crate profile sections.

Purpose: sccache caches entire compiled crate outputs, so unchanged kernel sub-crates
are skipped on rebuild. Incremental compilation is unsuitable for this project's
massive generated kernels — it still does full proc macro expansion and creates
gigabyte-scale caches. Removing redundant sub-crate profiles makes the workspace
root the single source of truth.

Output: Clean build configuration with sccache caching.
</objective>

**A) Edit `.cargo/config.toml`** to add sccache:

```toml
# Build configuration for CubeCL kernel crates.
#
# sccache: Caches compiled crate outputs so unchanged kernel sub-crates are
# skipped on rebuild. Incremental compilation is disabled (see Cargo.toml
# profiles) because sccache cannot cache incremental builds.
#
# jobs = 3: Each kernel sub-crate consumes 3-7 GB RAM during CubeCL proc macro
# expansion. jobs=3 keeps peak memory under ~21 GB on 24 GB systems.
[build]
compiler = "sccache"
jobs = 3
```

**B) Edit workspace `Cargo.toml`** profiles to set `incremental = false`:

```toml
# Reduce peak memory: CubeCL proc macro expansion generates massive IR.
# debug=0 skips LLVM debug scope tracking.
# codegen-units=16 bounds per-unit memory.
# incremental=false so sccache can cache compiled crates.
[profile.dev]
debug = 0
codegen-units = 16
incremental = false

[profile.test]
debug = 0
codegen-units = 16
incremental = false
```
  </action>
  <verify>
    <automated>grep -q 'compiler = "sccache"' /workspace/.cargo/config.toml && grep -q "incremental = false" /workspace/Cargo.toml && echo "PASS" || echo "FAIL"</automated>
  </verify>
  <acceptance_criteria>
- .cargo/config.toml has compiler = "sccache" and jobs = 3
- Cargo.toml profiles have incremental = false
  </acceptance_criteria>
  <done>sccache configured, incremental disabled at workspace level.</done>
</task>
