## The blocker — why a replan is needed

`audit_cube_launch.sh` reports **1677** `#[cube(launch_unchecked)]` attributes
vs **baseline 23** (P11-INV-5). This is **not** a Task-2 regression and **not**
an `emit.py` bug:

1. `emit.py` does not synthesize the `#[cube]` attribute — its docstring
   states so. The `#[cube(launch_unchecked)]` vs `#[cube]` choice is baked
   into the `cube_fn_src` the **translators** (`translate_{lda_v2,gga,mgga}.py`)
   pass in.
2. emit.py's design: a *routed* functional's entry wrapper — **one per output
   module** — carries `#[cube(launch_unchecked)]`. ~168 routed functionals ×
   ~10 output modules ≈ 1677. Even demoting the ~98 *unrouted* subcrates to
   plain `#[cube]` leaves the routed set at ~400–1000+ launchables.
3. **Plan-level contradiction:** 11-03 Task 2 mandates *preserving verbatim*
   the dispatch macros (`ten_arm_dispatch_gga!`, `mgga_zero_scalar_unpol_dispatch!`),
   which call `.launch_unchecked()` **per kernel function** — requiring every
   dispatched kernel to be `#[cube(launch_unchecked)]`. P11-INV-5 demands ≤23.
   Both cannot hold. ≤23 is only reachable via the manual's §5/§19
   re-architecture (a small set of generic launch kernels + `#[comptime]`
   functional selection), which contradicts the preserve-the-macros mandate.
4. The pre-Phase-11 baseline of 22–23 was measured on a tree whose dispatch
   layer **never compiled** (Blocker B1 + plain-`#[cube]` kernels with no
   `.launch_unchecked()` method) — it was never a working reference point.

**The replan must resolve this**, by either:
- revising/dropping P11-INV-5 (e.g. a new baseline reflecting the per-functional
  design, or counting routed-only launchables), **or**
- redesigning the dispatch architecture per `cubecl_macro_fanout_manual.md`
  §5/§19 (generic launch kernels + `#[comptime]` selection) as explicit tasks,
  touching the translators + `emit.py` + the dispatch generators + the
  dispatch macros.
