**Systematic fix for ArrayArg::from_raw_parts migration:**

CubeCL 0.10 changed the signature. Update all call sites to the new shape:

**Old pattern (CubeCL 0.9):**
```rust
#[cfg(test)]
fn test_pow() {
    let input = ArrayArg::from_raw_parts::<f64>(&handle, 10, 1);
    // ...
}
```

**New pattern (CubeCL 0.10):**
```rust
#[cfg(test)]
fn test_pow() {
    let input = ArrayArg::from_raw_parts(handle, 10);  // No generic, no stride
    // ...
}
```

**Steps:**
1. For each affected file, find all `from_raw_parts::<` calls in `#[cfg(test)]` blocks
2. Remove the generic parameter (e.g., `::<f64>` → nothing)
3. Remove the `&` from handle (e.g., `&handle` → `handle`)
4. Remove the stride argument (usually the third `1` or similar)
5. Keep the size argument (second position)

**Concretely:**
- `ArrayArg::from_raw_parts::<f64>(&handle, n, 1)` → `ArrayArg::from_raw_parts(handle, n)`
- `ArrayArg::from_raw_parts::<f64>(&client_handle, size, stride)` → `ArrayArg::from_raw_parts(client_handle, size)`
