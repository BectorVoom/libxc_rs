### Manifest format (planner choice — newline-delimited JSON per Claude's Discretion line in 6TH discussion log)

Each line is one record:
```json
{"batch_index": 0, "package": "libxc-kernel-lda_c_1d_csc", "family": "lda", "result": "ok", "wall_time_s": 12.4, "peak_rss_mb": 1843, "stderr_tail": null, "pass": 1}
```

Where:
- `batch_index`: 0-based batch number (0..ceil(273/20)-1)
- `package`: full cargo package name (`libxc-kernel-<func>`)
- `family`: one of `lda`, `gga`, `mgga`
- `result`: `ok` | `fail` (final disposition after up-to-2 passes)
- `wall_time_s`: float seconds for the LAST attempt's cargo invocation
- `peak_rss_mb`: integer MiB peak resident set size from `/usr/bin/time -v` (or psutil), measured for the LAST attempt
- `stderr_tail`: null on success; on failure, the last ~50 lines of cargo stderr captured as a JSON string
- `pass`: 1 (succeeded in parallel pass) | 2 (succeeded in sequential retry) | -1 (failed both passes)

The summary report (separate file, `.cache/batched-compile-sweep-summary.md`) aggregates: total swept, ok/fail counts per family, average + max peak-RSS per batch, total wall-clock.
