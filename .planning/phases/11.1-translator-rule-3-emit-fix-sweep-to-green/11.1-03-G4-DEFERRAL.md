# Phase 11.1 — G4 (full-649 f32 oracle sweep): DEFERRED to re-opened Phase 11

## Decision

G4 — the full-649 f32 oracle sweep with per-functional tolerance overrides (CONTEXT.md D-03/D-12,
the deferred D-24 / 11-08 Task 3 deliverable) — is **not run as part of 11.1**. It hands back to a
re-opened Phase 11 alongside the other deferred closure items (11-06 Legs 2/3/4 + Task 8, 11-08
Task 2, the D-LOCK-D idempotency proof, and `phase.complete 11`).

## Why deferred

**G4 inherently requires building all 281 kernel crates.** Unlike G3 (a single-functional canary
that was rewritten to build ONE kernel — see 11.1-03-G3-PARITY-LOG.md), G4 exercises *every* one
of the 649 functionals through `libxc_rs::eval::dispatch_*`. The dispatch is statically linked
against the entire kernel tree via the `libxc_rs` umbrella crate, so there is no way to evaluate
the full oracle without compiling all 281 kernels in one cargo invocation.

On this machine (30 GB RAM, 16 cores) that monolithic build:
- OOMs at the plan's `--jobs 3` (a prior session's attempt died mid-compile — see the original
  `11.1-03-G3-parity.log`, which was actually the all-kernel verify build, not a real G3 run),
- and at `--jobs 1` is a multi-hour cold build with residual codegen-stage OOM risk.

This is the same class of infeasibility-in-11.1 as the D-LOCK-D idempotency proof (see
`11.1-02-IDEMPOTENCY-DEFERRAL.md`), and the user elected the same disposition: keep 11.1's scope
narrow (translator Rule-3 emit correctness) and hand the all-kernel work to Phase 11.

## Additional finding that strengthens deferral

G3 root-causing uncovered a **systemic** parity gap: the Rust production dispatch does not
replicate libxc's `work_mgga` input regularization (the von Weizsäcker τ-clamp τ ≥ σ/(8ρ), and
likely other `work_*.c` preprocessing). See memory `project_translator_missing_workmgga_tau_clamp`.
A meaningful G4 f32 oracle sweep would surface this gap as widespread MGGA failures that are NOT
f32-precision issues and NOT tolerance-override candidates — they require the work-driver
regularization to be added to the translator first. That work belongs to re-opened Phase 11.

## Hand-back checklist (re-opened Phase 11)

- [ ] Add libxc `work_*.c` input regularization to the translator/dispatch (von Weizsäcker τ-clamp
      at minimum) — systemic, all MGGA. Until then, MGGA oracle parity for τ<τ_W inputs will fail.
- [ ] Build a memory-safe path to evaluate the full-649 oracle (e.g. feature-gate `libxc_rs`
      kernel deps by family so each family's oracle runs against only its kernels, in chunks),
      OR run the monolithic build at jobs=1 on adequate hardware.
- [ ] Run G4 (LIBXC_RS_F32=1 oracle sweep) with per-functional tolerance overrides bounded by the
      1e-3 hard ceiling (D-12).
- [ ] Then resume 11-06 Legs 2/3/4 + Task 8, 11-08 Task 2, D-LOCK-D idempotency proof, and
      `phase.complete 11`.
