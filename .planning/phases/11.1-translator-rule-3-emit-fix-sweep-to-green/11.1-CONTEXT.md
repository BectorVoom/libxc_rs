### P3-preventive taxonomy — comprehensive one-pass coverage

- **D-04:** The translator emit fix covers EVERY identifiable f64-literal position in chunk bodies in ONE pass, not iterative-extension. AP-8 forbids the latter. Position taxonomy:
  - **P1 (named-const ref in F arithmetic)** — `t_F * M_PI * t_F` → wrap via hoisted binding (see D-05)
  - **P2 (bare-literal tuple-return member)** — `(t6, t7, t8)` where any member is a bare f64 literal flowing to `(F, F, F)` return → wrap each f64 member per Rule 2/3 (D-06)
  - **P3 (let-binding RHS feeding F expression)** — `let t10 = M_CBRT3;` returned in F-typed body or used in F arithmetic downstream → wrap RHS at the let-binding site
  - **P4 (helper-call argument)** — `pow_1_3::<f64>(t11)` where `t11 = F::new(1.0) / M_PI` mixes F and f64 → caller-side: ensure the inner expr stays F (M_PI is the loose end); callee-side: turbofish per D-09
  - **P5 (single-expression body return)** — `pub fn ... -> F { M_CBRT3 }` → wrap as `F::cast_from(M_CBRT3)` (or use the hoisted binding when one exists)
  - **P6 (match-arm RHS, conditional RHS, closure body)** — any position where a bare f64 expression flows into an F-typed slot
- **D-05:** Named-const refs emit via hoisted per-fn binding, NOT inline per use:
  ```rust
  #[cube]
  pub fn ..._chunkN<F: Float>(t1: F, ...) -> F {
      let pi = F::cast_from(M_PI);          // hoisted once at top of body
      let cbrt3 = F::cast_from(M_CBRT3);    // ditto for every named const used
      // ... body uses `pi`, `cbrt3` as plain F-typed identifiers
  }
  ```
  Translator must (a) enumerate every named const referenced in a chunk body, (b) emit one let-binding per referenced const at the top of the body, (c) substitute each named-const occurrence in the body with the local binding name. Compile-time win on Brent-method bodies with 100+ M_PI uses; cleaner read; matches 11-PATTERN.md Rule 3 example.
- **D-06:** Literal-wrap shape follows 11-PATTERN.md Rule 2 / Rule 3 split:
  - **Short f32-compatible literals** (`0.0`, `1.0`, `2.0`, `0.5`, `-1.0`, `3.0`, etc.) → `F::new(<lit>)`
  - **F64 named consts** (`M_PI`, `M_CBRT3`, `SQRT_DBL_EPSILON`, `LOG_DBL_MAX`, `KF_CONST`, `RS_CONST`, `ERX`, `PI_TWO_THIRDS`, `POW_32PI_TWO_THIRDS`, `f64::MAX`, etc.) → `F::cast_from(<const>)` (via hoisted binding per D-05)
  - **Long f64 literals** that may lose precision in f32 (e.g., `1.7724538509055160`, `137.0359996287515`) → `F::cast_from(<lit_f64>)` to preserve precision in f64 mode; f32 mode accepts the narrowing cost (1e-6 tolerance per D-19a)
  - **Pure-integer literals in non-F positions** (`for _ in 0..N`, `arr[3]`, `0u32`, `MAX_TUPLE_ARITY = 12`) → left as concrete integers (Rule 2 exception)
- **D-07:** Boundary classification is position-driven, not value-driven. The translator looks at WHERE the literal/identifier is being emitted (tuple member of F-tuple return? RHS of let in F-typed body? arg to F-generic helper?) to decide the wrap shape. This requires real AST-or-semantic awareness, not just token regex. Implementation surface left to planner per D-15 (Claude's Discretion).

  - Adds an entry to `f32_tolerance_overrides.toml` with `(functional, derivative-order) → relaxed_tolerance` + a one-line rationale comment
  - Re-runs G4

  - HARD CEILING: 1e-3 (asserted in `f32_tolerance_for`); failures past 1e-3 escalate via /gsd:discuss-phase as a structural correctness issue, not a tolerance widening.
- **D-13:** Bounded translator-fix iterations: at most **N=3** fix→regen→sweep cycles. After the 3rd HALT with a new failure pattern, 11.1 HALTs to `/gsd:discuss-phase 11.1` for re-direction. Rationale: avoids AP-8 unbounded-extension trap; gives slack for unforeseen P-pattern sub-classes; the D-04 comprehensive-coverage choice should make 1–2 iterations the realistic case.
- **D-14:** First failure during sweep iteration (G1 or G2 pass 2) is the loop-trigger. The sweep tool's existing halt-and-surface behavior (per D-33) writes `.continue-here.md` with the failing functional + stderr digest; executor reads, diagnoses, fixes translator, runs `python3 tools/maple_to_kernels.py translate --all-families` (full-tree regen per D-LOCK-D), re-runs sweep. Repeat up to N=3. Each iteration is one atomic commit (translator change + regen diff + sweep manifest update).

### Claude's Discretion

- **D-15 — Emit implementation strategy (regex vs AST visitor in `cse.py`).** D-04's comprehensive coverage + D-06's Rule 2/3 split + D-07's position-driven classification + D-05's per-fn hoisting all imply AST-level / semantic awareness in the emit path — beyond what a simple regex extension delivers. D-16 (Phase 11's original decision) explicitly named `cse.py` as the AST-pass home; the regex-only `_wrap_f64_literals` was the interim path. 11.1's planner picks the exact shape: (a) full AST visitor in `cse.py` that walks the chunk body before emit, classifying every token by position; (b) regex extension with a tokenizer-light front-end; (c) hybrid (regex for literal-wrap pass + targeted AST walks for named-const hoisting and tuple-member fixing). Recommendation leans toward (a) for D-LOCK-D idempotency + AP-8 boundary discipline; (b) accepted if planner shows that token-position can be unambiguously regex-disambiguated against doc-comments and string-literals.
- **D-16 — Regen mechanism.** Default recommendation: full clean-slate regen via `python3 tools/maple_to_kernels.py translate --all-families` after each translator change (mirrors Deviation F's pattern at `4aaaaa7739` / `8a9f32091e` / `d26efabda6` — `ok=N skipped=0 failed=0` per family). Selective regen is allowed for debugging single-functional failures but the closing iteration MUST be full-tree to satisfy D-LOCK-D idempotency proof. Planner picks the exact `tools/maple_to_kernels.py` invocation shape (single per-family run vs three sequential).
- **D-17 — Deviation E/F dead-code removal mechanism.** After D-08 native emit lands and a full-tree regen produces identical output (proving native emit subsumes the substitution), the substitution block in `tools/translate_v2/*.py` is removed. Planner picks: delete the block outright, or annotate with `# SUPERSEDED 11.1 D-08 — kept for post-mortem` and remove in the next phase. Either is acceptable as long as the substitution is no longer called.
- **D-18 — Sweep tool `--include-deferred` extension.** Currently `batched_compile_sweep.py`'s default roster is 266 routed; the 7 D-11 deferred subcrates need explicit `-p` to compile. 11.1 needs them in G1+G2. Planner picks: (a) extend sweep tool with `--include-deferred` flag that adds the 7 deferred pkgs; (b) pass explicit `-p <pkg>` roster file; (c) skip deferred subcrates from sweep entirely and add a separate single-subcrate compile check.
- **D-19 — Per-fn hoisted-binding naming.** Names like `let pi = F::cast_from(M_PI);` need to be (a) collision-free with existing chunk-body local-variable names (which are `t1`, `t2`, ..., `t40620`) — short lowercase names like `pi`, `cbrt3`, `sqrt2` are safe; (b) consistent across chunks so a future grep yields predictable matches. Planner picks the name map (e.g., `M_PI` → `pi`, `M_CBRT3` → `cbrt3`, `SQRT_DBL_EPSILON` → `sqrt_eps`, etc.) or defers to a deterministic snake_case-of-symbol-name scheme.
- **D-20 — Sweep ordering within ALL_OK gates.** G1→G2→G3→G4 is the natural compile-then-numeric sequencing. Within G1 (and G2), the alphabetical-within-family order (`lda → gga → mgga`) of `batched_compile_sweep.py` is inherited. Planner confirms G3 sits cleanly between G2 (last compile gate) and G4 (first numeric gate).
