# Quick Task 260509-q03 — Maple-to-kernel unified driver

## Goal

A single entrypoint (`tools/maple_to_kernels.py`) that orchestrates the existing
maple2c→Rust kernel pipeline with one consistent CLI for splitting-criteria
knobs, so OOM mitigation knob-twiddling stops requiring three-tool memory.

This is **a thin orchestrator only** — no reimplementation of translation or
splitting logic. Existing tools remain authoritative; the new tool just
delegates with consistent flags.

## Splitting-criteria knobs (memory-locked semantics)

Per `feedback_splitting_terminology.md`, "fewer files / less aggressive
splitting" ⇒ RAISE the threshold values. Defaults pin the current repo state:

| Knob | Tool | Default | Effect |
|------|------|---------|--------|
| `--split-threshold N` (per-cube-fn line cap) | `translate_lda_v2.py`, `translate_gga.py`, `translate_mgga.py` | 100000 | Larger ⇒ fewer per-functional `.rs` files. |
| `--target-max N` (per-sub-crate line cap) | `split_lda_subcrates.py`, indirect for `split_oversized_*.py` | 500000 | Larger ⇒ fewer sub-crates. |

**Direction default for q03**: keep current larger thresholds (q01 raised
TARGET_MAX to 500_000; q02 raised SPLIT_THRESHOLD to 50_000 then q01-followup
to 100_000). Driver does NOT change repo state on its own; it surfaces knobs.

## Wrapped tools

Translators (Maple→Rust):
- `tools/translate_lda_v2.py` — single-functional or `--batch --write-to`
- `tools/translate_gga.py` — single-functional or `--batch --write-to`; accepts `--split-threshold N`
- `tools/translate_mgga.py` — single-functional or `--batch --write-to`; accepts `--split-threshold N`

Splitters (post-hoc partition for OOM mitigation):
- `tools/split_lda_subcrates.py` — accepts `--target-max=N`, `--dry-run`
- `tools/split_oversized_kernel.py <lda|gga|mgga>` — accepts `--dry-run`; TARGET_MAX is module-level constant
- `tools/split_oversized_mgga.py` — accepts `--dry-run`; TARGET_MAX is module-level constant

Existing orchestrator (will NOT be replaced):
- `tools/regen_phase09.py` — Phase 9 Plan 09-04 specific (single-sub-crate functionals only). Stays as-is; q03 driver is a generic complement, not a replacement.

## Tool surface

```
tools/maple_to_kernels.py [--dry-run]
  translate --family {lda|gga|mgga|all} [--split-threshold N]
  split     --family {lda|gga|mgga|all} [--target-max N]
  all       --family {lda|gga|mgga|all} [--split-threshold N] [--target-max N]
```

- `--dry-run`: print the underlying tool invocations and exit, do not run them.
- `--split-threshold` defaults to 100000 (matches current translator constants).
- `--target-max` defaults to 500000 (matches current splitter constants).
- For LDA, `translate` invokes `translate_lda_v2.py --batch --write-to crates/kernel-lda/src/funcs`. (LDA translator does NOT accept `--split-threshold`; the driver prints a warning when a non-default threshold is requested for LDA, and falls back to module-level constant.)
- For GGA/MGGA, `translate` invokes the respective `--batch --write-to` modes WITH `--split-threshold N`.
- `split` for LDA invokes `split_lda_subcrates.py --target-max=N`; for GGA/MGGA invokes `split_oversized_kernel.py <family>` (no `--target-max`; warns if non-default requested).
- `all` runs `translate` then `split` for the selected family.
