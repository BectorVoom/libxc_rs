# Quick Task 260509-q04 — `split_lda_subcrates.py --repack` to consolidate 4→2

## Why

User wants to "decrease kernels, especially LDA". Each LDA sub-crate is at
~10% of `TARGET_MAX=500_000`, so the bin-pack is over-fragmented:

| Sub-crate    | Lines  | Files | % of TARGET_MAX |
|--------------|--------|-------|-----------------|
| kernel-lda-1 | 49,917 |   100 |  10% |
| kernel-lda-2 | 37,718 |   285 |   8% |
| kernel-lda-3 | 49,728 |    32 |  10% |
| kernel-lda-4 | 49,997 |    34 |  10% |

The current `split_lda_subcrates.py` is split-only and idempotent — second
run prints "already split" and exits. To "decrease kernels by changing
tools", **extend the existing tool** rather than write a one-off.

## Direction (memory `feedback_splitting_terminology.md`)

| User says | Effect on bin count | Mechanical change |
|-----------|---------------------|-------------------|
| "decrease kernels" | FEWER bins | RAISE TARGET_MAX |

Total LDA = ~187K lines. With `TARGET_MAX=500_000` everything fits in ONE
bin. User picked **4→2** earlier (conservative, OOM headroom kept), so we
want a TARGET_MAX that produces 2 bins:

- 187K / 2 bins ⇒ each bin ~94K
- Pick `TARGET_MAX=100_000` for the repack run: large bin (~100K of
  lda_c_pk09 + pmgb06 + pw_erf + ksdt + 1d_ehwlrg + vwn_1) + small/medium
  bin (~88K of the remaining 35 small funcs).

## Tool change

Extend `tools/split_lda_subcrates.py`:

1. Add `--repack` flag.
2. When `--repack`:
   - Detect already-split state (kernel-lda-1..N exist).
   - Move per-functional dirs from each `kernel-lda-N/src/<func>/`
     back into `kernel-lda/src/<func>/` (the aggregator pre-split tree).
   - Drop the now-empty `kernel-lda-1..N` sub-crates' contents (we'll
     either reuse them or delete them in step 3).
   - Re-run the existing bin-pack on the gathered set with the active
     `--target-max` (default unchanged at 500K; CLI `--target-max=N`
     overrides to force a finer split).
   - Re-emit the new sub-crates `kernel-lda-1..M` (M from the new pack).
   - Update aggregator `kernel-lda/Cargo.toml`, `kernel-lda/src/lib.rs`.
   - Update workspace `Cargo.toml` `[workspace.members]` and
     `[workspace.dependencies]` for added/removed crates.
3. Without `--repack`, behavior is unchanged ("already split, exiting").
4. Idempotent: a second `--repack --target-max=X` with no changes is a
   no-op (gather → pack → no diff → exit cleanly).

## Tasks

1. Add `--repack` mode to `tools/split_lda_subcrates.py`. Reuses existing
   bin-pack helpers; new code path for the gather + workspace-rewrite
   steps.
2. Smoke `--repack --dry-run --target-max=100000`: print bin assignment +
   would-be moves + workspace-Cargo edits; no filesystem changes.
3. Execute `--repack --target-max=100000` live.
4. Confirm `kernel-lda-3`, `kernel-lda-4` directories no longer exist.
5. Confirm `kernel-lda/src/lib.rs` still re-exports all 41 LDA functionals.
6. Confirm workspace `Cargo.toml` no longer mentions `kernel-lda-3` or
   `kernel-lda-4`.
7. Commit tool change + structural diff atomically.

  `--target-max` further (more granular per-cube-fn split) or revert
