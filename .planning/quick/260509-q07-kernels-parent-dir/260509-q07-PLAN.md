# Quick Task 260509-q07 — `crates/kernels/` parent directory re-org

## Why

User wants families grouped under one parent for navigability:

```
Before                         After
crates/kernel-lda           →  crates/kernels/lda
crates/kernel-lda-1         →  crates/kernels/lda-1
crates/kernel-gga           →  crates/kernels/gga
crates/kernel-gga-1..5      →  crates/kernels/gga-1..5
crates/kernel-mgga          →  crates/kernels/mgga
crates/kernel-mgga-1..8     →  crates/kernels/mgga-1..8
crates/kernel-math          →  crates/kernels/math
```

The **path** changes; the **Cargo package names stay** (`libxc-kernel-lda`,
`libxc-kernel-gga-1`, `libxc-kernel-math`, etc.) so every Rust import
(`use libxc_kernel_lda::*;`) keeps working unchanged. Same compilation
profile (each sub-crate still its own rustc compile unit) → same RAM
behaviour, no OOM-mitigation regression.

## Scope

| Layer | Change |
|-------|--------|
| Filesystem | `git mv crates/kernel-X crates/kernels/X` for all 17 dirs (drops `kernel-` prefix). |
| Workspace `Cargo.toml` | 17 `[workspace.members]` paths and 17 `[workspace.dependencies]` paths updated. |
| Each sub-crate `Cargo.toml` | `path = "../kernel-math"` → `"../math"`, aggregator path-deps similarly. |
| Splitter tools (7 files) | Path constants and SUBCRATE_RE regexes updated to `crates/kernels/<family>` and `^<family>-\d+[a-p]?$` (no `kernel-` prefix). |
| `src/` Rust code | NO changes — only doc comments mention `crates/kernel-*` paths; staleness flagged but not blocking. |

  - All Cargo `path = ...` references resolve.
  - Cargo package names (`libxc-kernel-{lda,gga,mgga,math,lda-1,gga-1..5,mgga-1..8}`) unchanged.
  - Splitter tools point at the new layout; their regexes match `^<family>-\d+[a-p]?$` (no `kernel-` prefix).

## Out of scope

  (staleness only — flag in SUMMARY).
- `cargo check` verification (RAM-constrained; defer to user).
- Updating non-splitter tools (translators, generators) — they reference
  paths via the splitter tools' constants in many cases. If grep shows
  hardcoded paths in tools NOT in the splitter list, they'll be flagged
