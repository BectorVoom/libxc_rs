### Tool fix bundled with MGGA commit

`tools/rebatch_mgga.py:368 update_workspace()` resolved the project
`Cargo.toml` to the literal path `crates/Cargo.toml` because
`os.path.dirname("crates/kernels")` is `"crates"` — a latent q07
regression introduced when kernels moved under `crates/`. The
splitter completed the per-crate creation + aggregator update before
crashing on the workspace edit. Fix: take `os.path.dirname` twice
(`"crates/kernels"` → `"crates"` → `""`) and fall back to bare
`"Cargo.toml"`. The crashed run's workspace edit was completed
manually by importing the fixed module and calling
`update_workspace(14)` directly before the commit.

- **Dispatch regeneration.** Initially listed in the plan as a known
  q06 follow-up. On inspection, `tools/generate_gga_dispatch.py` regenerates
  `src/eval/gga_dispatch/` from a *fixed* phase-4 roster
  (batch ids `4g`, `5g`, `6d`, `8d`, `12..22`) and the dispatch
  routes through `crate::kernel::gga::batchN` — paths *inside* the
  root `libxc_rs` crate, not the `libxc-kernel-gga-N` sub-crates.
  Sub-crate count and dispatch batch ids are independent layers, so
  q08's resplit does not require dispatch changes. A trial regen
  reverted hand-tuned CR-07 typed-error handling (replaced with
  `expect()` panics) and was reverted with `git checkout`. q06's
  "regenerate dispatch" follow-up note was based on a misread of
  the layering and is now invalid.
- LDA dispatch (`src/eval/lda_dispatch/` if any): same reasoning.
- `cargo check`/`cargo test` validation: deferred to user (RAM rule).
