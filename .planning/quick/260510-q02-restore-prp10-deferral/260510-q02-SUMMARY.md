# Quick Task 260510-q02: Restore mgga_x_2d_prp10 module deferral

## Outcome

Re-commented-out the `pub mod mgga_x_2d_prp10;` declaration in `crates/kernels/mgga-12/src/lib.rs`. `cargo build -p libxc-kernel-mgga-12` no longer enters the prp10 directory, so the missing-Bessel E0425/E0433 errors disappear by construction (40+ errors across `vxc_pol`, `vxc_unpol`, `fxc_pol`, `fxc_unpol`, `kxc_pol`, `kxc_unpol`, `lxc_pol`, `lxc_unpol`).

## Root cause (regression mechanism)

`mgga_x_2d_prp10` (libxc id 211) needs `xc_bessel_I0` and `xc_bessel_I1` (modified Bessel I-functions). These functions do not exist in `libxc-kernel-math` — there is no `bessel.rs`, no entries in `crates/kernels/math/src/lib.rs`, and no callers anywhere outside the prp10 module itself.

Phase 4 documented this:
- `.planning/phases/04-bulk-kernel-translation/04-04-SUMMARY.md:120` — "modules commented out in their per-batch `lib.rs` (e.g. `mgga_x_2d_prp10` needs Bessel I0/I1, …)"
- `src/model/mgga_functional.rs:23` — "the variant is therefore absent from this enum; its id (211) returns `UnsupportedFunctional` via the default arm of `from_id`"

The module was originally commented out in `crates/kernel-mgga-35/src/lib.rs`. Subsequent rebatching tooling (`rebatch_mgga.py` in q05/q06/q08, plus `split_oversized_mgga.py` from q01) regenerates `lib.rs` from `os.listdir(src_dir)` — which silently re-adds every directory it finds, including the previously-commented-out `mgga_x_2d_prp10/`. The translator never deleted the source files (correctly — they're still valid translations awaiting Bessel support), so the directory was always there to be re-discovered.

This is a latent class of bug: any `lib.rs` directive that diverges from "include every subdirectory" gets erased on the next regeneration pass. Other directories under `mgga-12/src/` that should remain compiled (e.g. `mgga_k_lk`, `mgga_k_pgslb`, `mgga_x_m06l`, `mgga_x_m08`, `mgga_x_ms`, `mgga_x_msb` — the "template kernels" with no unique libxc id, per `mgga_functional.rs:36-41`) are not affected because they ARE supposed to compile; only their dispatch wiring is missing, which is orthogonal to the build state.

## Build verification

Per the RAM-constrained-machine memory rule, no in-session `cargo check` was run on `mgga-12` (an attempt to do so during investigation OOM-killed before completion — even `cargo check` cold-builds the full math + cubecl-cpu dep tree on top of an already-12 GB system). The fix is mechanically verifiable by inspection: removing the `pub mod` declaration excludes the prp10 directory from the crate graph entirely, so the missing-symbol errors cannot be reached. Operator verification step:

```bash
cargo check -p libxc-kernel-mgga-12 --message-format=short
```

Expected: clean check (no E0425/E0433 from prp10), peak RSS bounded by mgga-12's other functionals.

## Known follow-ups (NOT introduced by q02)

- Splitter tools (`rebatch_mgga.py`, `split_oversized_mgga.py`) regenerate `lib.rs` from filesystem listing without honoring deferred-module markers. Possible remediation: either move deferred kernel sources out of `mgga-N/src/<name>/` into a dedicated `deferred/` subtree the splitter ignores, or add a `# DEFERRED: <reason>` sentinel file convention the splitters check before emitting `pub mod`. Out of scope for q02 — flagged for a future tooling task.
- Implementing Bessel I0/I1 (e.g. polynomial Chebyshev approximations) as `#[cube]` functions in `kernel-math` would un-defer prp10. Substantive work, separate task.
- The 5 "template kernels" with no unique libxc id (`mgga_k_lk`, `mgga_k_pgslb`, `mgga_x_m06l`, `mgga_x_m08`, `mgga_x_ms`, `mgga_x_msb`) are tracked separately as a Phase-4 follow-up; nothing changes here.

## Postscript: orchestration mishap

During this task I attempted `git add crates/kernels/mgga-12/src/lib.rs && git commit -m ...`, not realizing the user's pre-session index already had ~6849 staged files (pre-existing planning-system reorg, log artifacts, target/ files, etc.) — which got swept into commit `22e2a245`. I caught it from the commit's stat (6850 files, 9.8M lines deleted), reset with `git reset --soft HEAD~1`, restored the index to its pre-session state via `git restore --staged crates/kernels/mgga-12/src/lib.rs`, and re-committed using `git commit --only -m "..." -- crates/kernels/mgga-12/src/lib.rs`. The user's pre-session staging is preserved exactly as it was. Lesson saved to memory: when other index entries exist that aren't part of the current task, always use `git commit --only -- <path>` (or the unflagged path-scoped form) so the committed contents match the active task scope.
