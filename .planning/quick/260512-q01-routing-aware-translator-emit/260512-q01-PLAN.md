# Quick Task 260512-q01: Routing-aware translator emit

## Problem

`tools/translate_{lda_v2,gga,mgga}.py` emit every main-entry kernel as
`#[cube(launch_unchecked)]` regardless of whether `<X>Functional::from_id`
actually routes the functional. The launch-wrapper code generated for
unrouted functionals is dead and inflates proc-macro RAM during
`cargo check` (see `docs/manual/Cubecl/cubecl_macro_fanout_manual.md`
Anti-pattern 1).

Recent work demoted these by hand per-crate (see commits b8b17f77,
89b21d89, dd284651, ...). The next translator regen would reintroduce
them all.

Compounding bug: `tools/demote_unrouted_kernels.py` globs the
pre-move layout `crates/kernel-{family}*/` and silently finds zero
functional dirs on the post-move `crates/kernels/{family}-N/` tree, so
the post-hoc cleanup is currently a no-op.

## Scope

Two-file fix + verification. No algorithm work — the splitter
algorithm-floor (`[[project_splitter_algorithm_floor]]`) is out of scope.

## Tasks

### T1 — Shared routing helper `tools/kernel_routing.py`

**files:** `tools/kernel_routing.py` (new)
**action:** Extract `parse_routed_funcnames` + `variant_to_snake_candidates`
from `demote_unrouted_kernels.py` into a standalone module. Expose
`routed_funcnames(family: str, known_dirs: set[str] | None = None) -> set[str]`
that reads `src/model/{family}_functional.rs`. LDA uses
`Ok(Self::Variant)` arms; GGA/MGGA use `Self::Variant => "name"` arrows.
**verify:** `python3 -c "from tools.kernel_routing import routed_funcnames; print(len(routed_funcnames('gga')))"` returns 105.
**done:** module created; LDA, GGA, MGGA all return the expected counts (37+, 105, 25).

### T2 — Wire routing into 3 translators

**files:** `tools/translate_lda_v2.py`, `tools/translate_gga.py`, `tools/translate_mgga.py`
**action:** Around the `cube_attr = '#[cube]' if fn_suffix.startswith('_part') else '#[cube(launch_unchecked)]'`
line in each translator, look up whether `func_name` is in the routed set.
If unrouted, force `cube_attr = '#[cube]'` even for main-entry kernels.
Cache the routed set at module load to avoid re-parsing per call.
**verify:** Regenerate one unrouted LDA (e.g. `lda_c_pk09`) into a tempdir
and confirm `grep -c launch_unchecked` returns 0. Regenerate one routed
LDA (e.g. `lda_c_vwn`) and confirm the main-entry kernels emit
`#[cube(launch_unchecked)]`.
**done:** both regen samples behave correctly.

### T3 — Fix glob + share helper in `demote_unrouted_kernels.py`

**files:** `tools/demote_unrouted_kernels.py`
**action:** Update `collect_func_dirs` glob from `kernel-{family}*` →
`kernels/{family}*` so it sees the post-move layout. Replace inline
`parse_routed_funcnames` with `from kernel_routing import routed_funcnames`.
Verify dry-run reports a non-zero unrouted set on at least one family.
**verify:** `python3 tools/demote_unrouted_kernels.py --dry-run` reports
non-zero "Unrouted (demote candidates)" counts that match `unrouted` derived from `func_dirs - routed`.
**done:** dry-run output is non-trivial.

### T4 — One-shot cleanup of in-tree launch_unchecked

**files:** none directly; runs fixed demoter on `crates/kernels/`
**action:** Run `python3 tools/demote_unrouted_kernels.py` (not dry-run).
Should reduce `grep -rc '^#\[cube(launch_unchecked)\]' crates/kernels` from 54 →
near zero (only routed-functional entry kernels keep it).
**verify:** Final `grep` count matches expected residue (entry kernels of
routed functionals only; e.g. lda_c_pk09's 32 should drop because it's deferred).
**done:** count drops; the only remaining `launch_unchecked` lines belong
to routed functionals.

### T5 — Static + sample-regen verification

**files:** none modified; verification only
**action:**
- Before/after `launch_unchecked` count
- Single-functional regen sample (lda_c_pk09 → tempdir) to prove translator
  no longer emits `launch_unchecked` for it
- No full `cargo check` — RAM-budget reasons, and the change is a
  pure source-code substitution that can't introduce semantics changes
**done:** SUMMARY.md captures before/after counts + regen test output.

## must_haves

- T1, T2, T3, T4, T5 all complete
- The translators no longer emit `launch_unchecked` for unrouted functionals
  on regen
- Tree state has the residual launch_unchecked cleaned up
- No source-code semantics changes (attribute-only edits)

## Out of scope (deferred)

- Further splitting of single-output-component giants (algorithm work,
  see `[[project_splitter_algorithm_floor]]`)
- Full `cargo check -j 1` validation across all kernel crates
  (RAM-budget; user can opt in afterward)
- Migrating `crates/kernels/<family>/` (the umbrella crate) — not affected
