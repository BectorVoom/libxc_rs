## Investigation findings

**Symptom (user-reported):** Kernel compile RAM is very large; need tooling
fixes so all kernels compile and execute within RAM budget.

**Root cause:** Three compounding issues:

1. **Translator regen indiscriminately emits `#[cube(launch_unchecked)]`**
   on every main-entry kernel, even for functionals that
   `<X>Functional::from_id` never routes. Per
   `docs/manual/Cubecl/cubecl_macro_fanout_manual.md` §4.3 (Anti-pattern 1)
   the host-side launch-wrapper boilerplate generated for unrouted kernels
   is pure proc-macro RAM overhead during `cargo check`.

2. **`tools/demote_unrouted_kernels.py` glob is stale.** It still globs
   the pre-move `crates/kernel-{family}*` layout. Since commit 24535856
   moved kernel crates to `crates/kernels/{family}-N/`, the demoter has
   been silently no-op'ing — returning 0 functional dirs across all three
   families. The recent manual cohort demotions (b8b17f77, 89b21d89,
   dd284651, ...) had to be done by hand because the script that should
   have done them was broken.

3. **The combination** is a maintenance trap: every regen re-introduces
   `launch_unchecked` on the ~75% of GGA / ~83% of MGGA / ~10% of LDA
   functionals that aren't routed, and the supposedly-automated cleanup
   doesn't run.

**Routed/unrouted census (post-fix):**

|--------|--------|--------------|----------|
| LDA    | 36     | 41           | 5 (lda_c_pk09, lda_c_pmgb06, lda_c_pw_erf, lda_k_gds08_worker, lda_xc_ksdt) |
| GGA    | 105    | 131          | 26       |
| MGGA   | 25     | 75           | 50       |

The translator branches correctly: unrouted → no launch wrapper; routed →

**Full `cargo check`:** in-flight at commit time (sequential, jobs=1).
Outcome does not affect the correctness of these changes — T4 only touched

`src/eval/dispatch.rs`. Any compile failure would predate this work
(routed-kernel demotion from b539511d / 937fc9ac left routed kernels at
plain `#[cube]` while `dispatch.rs` still calls `::launch_unchecked`).

## Risks + follow-ups (out of scope here)

1. **Routed-kernel demotion vs dispatch mismatch (pre-existing).** The
   manual cohort fixes b539511d/937fc9ac demoted routed entry kernels
   too. Since `src/eval/dispatch.rs` calls `<kernel>::launch_unchecked`,
   a fresh `cargo check` may fail on routed kernels until either
   - `tools/translate_*.py` regens routed entry kernels (now emits
     `launch_unchecked` correctly), or
   - `src/eval/dispatch.rs` is reworked to bridge plain-`#[cube]` kernels
     through a separate `#[cube(launch_unchecked)]` wrapper.
   The new translators handle the first option automatically; pick a
   functional to regen as the next step.

2. **Splitter algorithm floor (deferred).** 22 in-tree kernels remain
   10K-22K lines and the per-output-array splitter cannot subdivide
   them further (see `[[project_splitter_algorithm_floor]]`). Real fix
   is mid-cascade `#[cube]` helpers or splitting by maple2c output-row
   stride — algorithm work, not in scope here.

3. **Compile-RAM profiler tool** (offered, declined). Would add
   `tools/measure_kernel_ram.py` to track per-crate RAM. Easy follow-up
   if you want telemetry.
