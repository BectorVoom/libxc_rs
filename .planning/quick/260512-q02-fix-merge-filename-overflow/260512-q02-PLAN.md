# Quick Task 260512-q02: Fix translator merge-suffix filename overflow

## Problem

User reported `cargo check` OOM specifically on `libxc-kernel-mgga-14`
(while lda-2 and mgga-2 compile fine). Investigation showed
`mgga-14/mgga_x_br89_explicit/lxc_pol.rs` is **21,679 lines** in a
single function — well above SPLIT_THRESHOLD=6000.

The file is stale (mtime 2026-05-10) — it predates the
SPLIT_THRESHOLD=100K → 6K lowering on 2026-05-12 (commit 5cc3f508).
But running the current translator on it crashes:

```
OSError: [Errno 36] File name too long:
'.../mgga_x_br89_explicit/lxc_unpol_part0_zk_vrho_vsigma_..._v4rho2lapl2.rs'
```

Root cause: `merge_small_splits` in `tools/translate_{lda_v2,gga,mgga}.py`
concatenates output-field suffixes during merge:
`f'{prev_suffix}_{suffix}'` — unbounded growth. lxc-level kernels have
40+ output components, producing 400+ char filenames that exceed
Linux's 255-byte per-component limit.

## Tasks

### T6 — Cap merge suffix length (3 translators)

**files:** `tools/translate_lda_v2.py`, `tools/translate_gga.py`, `tools/translate_mgga.py`
**action:** Add `_capped_merge_suffix(prev, new)` helper before
`merge_small_splits`. Truncate combined suffix at `_SUFFIX_MAX_CHARS=60`
and append `_etc` marker if truncated. Uniqueness is preserved by the
`_partN` index in the caller.
**verify:** Re-run `translate_mgga.py libxc-master/.../mgga_x_br89_explicit.c
mgga_x_br89_explicit --write-to <tmp> --incremental` without OSError.
**done:** All three translators produce capped suffixes.

### T7 — Regen mgga-14's two stale large functionals

**files:** `crates/kernels/mgga-14/src/mgga_x_br89_explicit/`,
`crates/kernels/mgga-14/src/mgga_x_r4scan/`
**action:** `rm -rf` the existing dirs and rerun the fixed translator.
Both functionals are unrouted in `MggaFunctional::from_id` so they emit
plain `#[cube]` (no launch wrappers).
**verify:** Max line count per file is <SPLIT_THRESHOLD; longest
filename <100 chars.
**done:** mgga-14 max file drops 21,679 → 5,352 lines.

## must_haves

- Translator no longer OSError's on regen of high-derivative-order kernels.
- mgga-14 max line count falls below the empirical proc-macro RAM ceiling
  (~6K based on lda-1 baseline).
- No source-code semantics changes (line bodies preserved; only file
  partitioning and naming changes).
